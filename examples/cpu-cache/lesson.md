# CPU 缓存，数据的近路

目标：解释缓存命中/未命中、整块搬入、时间与空间局部性、容量和 LRU 对结果的影响；能预测一次读取是否需要内存搬运。

## 运行

Node.js 22.12+。本目录执行 `npm ci`，然后 `npm run dev`。验证：`npm test`、`npm run build`。构建预览：`npm run preview`，或用任意 HTTP 静态服务器托管 dist。浏览器运行不需要 AI 服务、账号或网络字体。

## 教学步骤

1. 认识结构：CPU 芯片剖开示意中的处理核心与缓存，旁边的主内存。
2. 第一次读取：空缓存，读取 A[0]，从内存复制整块 A[0…3]。
3. 用上局部性：0 → 0 → 1 → 2 → 3，区分时间与空间局部性。
4. 容量与替换：0 → 4 → 0 → 8 → 4，命中更新 LRU；两行时淘汰 A[4…7]，最后一次读取再次未命中。
5. 改变再验证：连续与交错访问同一组 16 个元素，对比两行和四行缓存。

## 模型与视觉边界

一层、只读、全相联缓存，LRU 替换。A[0…15] 每元素 4 字节，每行含四个元素（16 字节），容量 2 或 4 行。行大小为便于观察的教学取值，不是通用 CPU 规格。忽略多级缓存、预取、并行、写入、地址转换与一致性。

结构位置、尺寸、数据路径均为示意；彩色表示按块身份保持一致，不是实际电子轨迹。读取产生副本，主内存原数据不消失。动画时间用于解释，不代表真实硬件延迟；统计只计已完成的读取。

连续为 0…15。交错为 0,4,8,12,1,5,9,13,2,6,10,14,3,7,11,15；两者数据集合与请求数相同。
